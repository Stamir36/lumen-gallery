## 1. Correctness / data

### 1.1 Scan upsert compares swapped columns — CONFIRMED (high)
`src-tauri/src/scan.rs:133`

```sql
ON CONFLICT(path) DO UPDATE SET ... size = excluded.size, mtime = excluded.mtime
WHERE media.mtime IS NOT ?5 OR media.size IS NOT ?6
```

Bind order is `?1 root_id, ?2 path, ?3 kind, ?4 ext, ?5 size, ?6 mtime`,
so the guard compares **stored mtime against the incoming size** and **stored size
against the incoming mtime**. mtime (unix seconds, ~1.7e9) and size (bytes, 1e4–1e9)
are never equal, so the condition is true for *every* row on *every* rescan.

Effects: the rescan "changes" counter is meaningless; every unchanged folder still
produces one UPDATE per row; WAL grows and the writer queue stays busy. This is why
a rescan of a 9.4k library can never report "0 changes".

Fix (S1.8): compare against `excluded.*` and prove it with an in-memory regression
test that runs the *real* statement: identical re-upsert ⇒ `changes = 0`,
modified mtime ⇒ `changes = 1`.

### 1.2 Bulk favorite / trash use a broken placeholder list — CONFIRMED (high)
`src/lib/mediaActions.ts:22`

```ts
function placeholderList(count: number, startAt = 2) { ... `?${i + startAt}` }
...
`UPDATE media SET favorite = ${...} WHERE id IN (${placeholderList(ids.length)})`, ids
```

The generated list starts at `?2`, but the parameter array is the raw `ids` (N binds).
The first id therefore binds to `?2`, `?1` is never bound, and the last id has no
parameter. Multi-select favorite/trash and the selection bar fail (or act on the wrong
rows). Single-row `toggleFavorite` uses `?1` and is unaffected.

Fix (S1.7): placeholders start at `?1`, chunk to ≤512 params, check
`rows_affected > 0` and toast on mismatch.

### 1.3 Writes still bypass the single writer — CONFIRMED (high)
The Phase 3.7 single-writer task only owns the paths routed through it:

| path | file:line | shape |
|---|---|---|
| video thumb upsert | `src/lib/thumbs.ts:340` | `UPDATE media SET thumb_path …` via the sql plugin |
| cache clear reset | `src-tauri/src/cache.rs:59` | `UPDATE media SET thumb_path = NULL …` on the pool |
| language | `src/i18n/index.ts:54`, `:94` | `INSERT INTO settings …` on the pool |
| scrub rate | `src/lib/settings.ts:50` | `INSERT INTO settings …` on the pool |
| external player | `src/pages/SettingsContent.tsx:355` | `INSERT INTO settings …` on the pool |

The video upsert is the one in the user's log (`elapsed=1.673s`, `elapsed=1.310s`) —
it contends with the thumbnail batch transactions, which is exactly the 1–7 s
single-row write the writer was introduced to remove.

Fix (S1.12): route all of them through the writer (internal Rust variants + the
whitelisted `db_exec` for the frontend), keeping a browser fallback for `#/grid-demo`.

### 1.4 First-open flicker — CONFIRMED (medium)
`src-tauri/src/lib.rs:96` resolves the pool lazily (up to 30 × 500 ms) before it sets
pragmas, spawns the writer and extends the asset scope. `src/App.tsx:101` starts
`getDb()` + `load()` + the first `list_media` immediately. Queries issued in that
window hit an unconfigured backend: no `busy_timeout`, no writer, and thumbs whose
files are outside the runtime asset scope. That is the visible first-open flicker.

Fix (S1.10): emit `backend-ready` after writer + asset scope init, expose a
`backend_ready` probe for the "event fired before the listener attached" race, and
make the first library query await it.

### 1.5 Watchers are not restored at boot — CONFIRMED (medium)
`spawn_watcher` is only called from `add_root` (`src-tauri/src/commands.rs`).
`WatcherRegistry` starts empty on every launch, so after a restart no root is watched
and new files stay invisible until a manual rescan.

Fix (S1.11): on boot, for each stored root, spawn the watcher if the directory exists.

## 2. Thumbnails (the user-visible pain)

### 2.1 The worker limit is per call, not app-wide — CONFIRMED (high)
`src-tauri/src/thumbs.rs` (`generate_thumbs`): `Semaphore::new(WORKERS)` is built
inside every invocation. The frontend flushes in batches of 48, so K concurrent
calls give K×4 parallel decodes rather than 4. The result array is also returned only
after the whole batch resolves, so nothing streams to the UI mid-batch.

Fix (S1.2): one managed, app-wide semaphore (workers from settings, default 4),
in-flight dedupe by `(id, mtime, size)`, sub-batches of 24 with incremental delivery.

### 2.2 Warm tiles are re-enqueued — CONFIRMED (medium)
`src/lib/thumbs.ts` `enqueueRows` skips only ids already in the *store*; rows that
already have `thumb_path` in the DB but no store entry are enqueued anyway, so the
first view asks Rust to "generate" thumbs it can return from cache. The tile also
renders shimmer until that round trip lands, which is the placeholder flash.

Fix (S1.1/S1.6): seed the store from `thumb_path` at ingest (instant
`convertFileSrc` render); enqueue only `thumb_path == null` rows whose version is new.

### 2.3 Validity is keyed on mtime alone — CONFIRMED (medium)
`src-tauri/src/thumbs.rs:186` (`thumb_mtime == c.mtime && exists`) and `:173`
(`thumb_error && thumb_mtime == Some(c.mtime)`). `thumb_size` does not exist; a file
replaced with the same mtime but a different size keeps a stale thumbnail, and a
previously failed row retries only when the mtime moves.

Fix (S1.4): migration v5 adds `thumb_size`; validity = `(id, mtime, size)`; on change
delete the stale file, clear `thumb_path`/`thumb_error`, regenerate — `thumb_error`
rows included.

### 2.4 No `thumbs-ready` event exists — CONFIRMED (high)
`grep -r "thumbs-ready" src-tauri/src` → 0 matches. The writer has no `AppHandle`, so
nothing can be pushed to the UI after a batch commit; tiles can only learn about a new
thumb from the `generate_thumbs` return value, and a row that is generated while
off-screen has no path until the next refetch.

Fix (S1.3): the writer emits `thumbs-ready {ids}` after each committed flush; the
frontend patches the react-query row cache for those ids (warm source of truth) and
clears stuck placeholders.

### 2.5 Browser fallback is per-id and in-memory only — CONFIRMED (medium)
`src/components/library/ThumbTile.tsx`: the "tried once" marker is
`localStorage["thumbFallbackTried:<id>"]` — not version-keyed, so a replaced file is
never re-tried; and the decoded `data:` URL lives only in component state, so it is
lost on unmount and re-decoded (or lost entirely) on the next scroll. Undecodable
files still show `FileWarning` + ext chip, which is correct, but the *decodable by
WebView* ones pay this cost forever.

Fix (S1.5): write the decoded bitmap (or the raw data URL) to `appCacheDir/thumbs`
via the fs plugin, record it through the writer, keep the negative marker keyed by
`(id, mtime, size)`.

### 2.6 `db_exec` leaks the statement text — CONFIRMED (low, but unbounded)
`src-tauri/src/commands.rs:45`: `Box::leak(sql.into_boxed_str())` to satisfy the
writer's `&'static str`. Every heart click leaks its SQL string forever.

Fix: let `Write::Immediate` carry an owned `String`.

## 3. UI / UX

### 3.1 Explorer duplicates folders on both panes — CONFIRMED (medium, user-reported)
The explorer renders `FolderTree` on the left *and* `FolderShelf` above the content,
so the same directories appear twice; the shelf was requested removed from the gallery
but is still mounted in explorer. Folder covers do not render in the shelf until a
thumb exists.

Fix (S1.9): a persisted `tree | grid` sub-toggle — `tree` = tree left + contents
right and **no** shelf; `grid` = **no** tree, wrapping folder-card grid + the current
folder's media. Never both. v2.2 gutters applied to folder-mode grids.
