# Visual regression (Playwright)

Скриншот-тесты ключевых поверхностей UI. Запуск: `pnpm e2e`.

## Как это работает

- Приложение живёт в обычном Chromium против Vite dev-сервера (конфиг
  поднимает его сам). Все QA-маршруты (`#/grid-demo`, `#/style`,
  `#/settings`, `#/onboarding`) работают без Tauri — IPC огорожен
  `tauriAvailable()`.
- Первый запуск на машине пишет базлайны:
  `pnpm e2e --update-snapshots`.
- Дальше каждый прогон попиксельно сравнивает экран с базлайном
  (`maxDiffPixels` допускает антиалиасинг). Регрессия радиуса/blur/отступов
  ловится без ручной сверки.

## Базлайны НЕ в git

`e2e/__screenshots__` в `.gitignore`: пиксельные базлайны зависят от машины
(шрифты, GPU-растеризация WebView/Chromium). Каждый разработчик/CI-агент
записывает свои один раз. Отчёт о расхождениях: `pnpm e2e show-report`.

## Детерминированность

- анимации выключены дважды: `reducedMotion: reduce` в конфиге + собственные
  `prefers-reduced-motion`-ветки приложения;
- шрифты ждутся явно (`document.fonts.ready`) перед каждым снимком;
- летучий хром (часы, спиннеры) скрывается `freezeVolatile()` в спеке;
- `data-volatile` на элементе — способ пометить новую летучую зону.
